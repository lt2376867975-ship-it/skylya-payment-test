# 2026-08-27 付费一次性邀请码原型与正式发布

## 目标与边界

- 官网先提供手机号和“我已付款”的模拟入口，不接真实支付渠道。
- 付款模拟成功后签发真实邀请码，短信目标文案为“您的邀请码是：xxx”。
- 主用户端手机号注册必须填写邀请码；邀请码必须存在、未过期且只能成功注册一次。
- 2026-08-27 已按最小范围正式发布；真实支付渠道仍不在本轮范围，“我已付款”继续是受生产开关保护的演示入口。

## 查清的真实链路

- 官网当前入口是 `Skylya 官网7.30`，主用户端是 `matching-agent/newSkyLiaUi v1`。
- 注册链路为用户端 `AuthApi` → Gateway/Auth 注册接口 → `AuthServiceImpl` → User Feign → `InternalUserController` → `UserServiceImpl` → MySQL。
- 旧 `beta_invite_codes` 仅存在于历史 SQL，V6 当前运行链路没有使用；管理后台现有 invite-codes 页面是注册容量统计，不是真实邀请码，因此本次新建独立 `paid_invite_codes`，未恢复旧表。
- 短信复用 Auth 现有阿里云短信提交与发送台账能力，新增 `PAID_INVITE_CODE` 场景和独立模板配置。

## 实现

### 官网与用户端

- 官网新增 `PaidInvitePurchase` 卡片：输入手机号、点击“我已付款”、展示处理态，成功后显示真实邀请码和短信目标文案。
- 用户端注册页新增必填付费邀请码，发送验证码前和最终注册时都传给后端。
- 未注册手机号从登录切换注册时，不再绕过邀请码自动发送注册验证码。
- 微信手机号新注册票据携带邀请码；已存在用户登录不要求邀请码。

### 后端与安全

- 新增 `POST /api/v1/auth/invite-codes/simulate-payment`，默认由 `SKYLIA_INVITE_PURCHASE_SIMULATION_ENABLED=false` 关闭，并按手机号做 60 秒冷却。
- User 服务签发 `SKY` 开头的邀请码；默认有效 30 天，可由 `SKYLIA_INVITE_VALID_DAYS` 调整。
- 数据库不保存邀请码或手机号明文，只保存 HMAC blind index、脱敏手机号、状态、签发/过期/使用时间和支付引用。
- 注册验证码发送前先校验；最终创建用户后，在同一数据库事务内执行带 `unused` 状态和过期条件的原子更新。并发或第二次使用只能有一个请求核销成功。
- 手机号、邮箱和微信手机号的新注册入口均已收口；无效、已使用、过期邀请码返回独立业务错误。
- 短信模板配置为 `ALIYUN_SMS_PAID_INVITE_CODE_TEMPLATE_CODE`。阿里云模板 `SMS_512410029` 已审核通过，签名为“北京斯凯利亚科技”，变量名为 `code`。

### 数据与部署材料

- 新增源码迁移 `matching-agent/skylia-cloud/doc/sql/99_paid_invite_codes.sql`。
- 新增服务器迁移 `server-script/sql/157_paid_invite_codes.sql`，与源码迁移 SHA-256 一致。
- 同步后端和服务器两份 `schema_full_ddl.sql`。
- Compose 已透传短信模板、模拟开关和有效期配置；源码默认关闭模拟开关，正式服本次为验收演示按 key 显式启用。

- 服务器与工作区未配置受控验收手机号；为避免误发给任意生产用户，真实 `SendSms` 提交和页面成功回包暂待用户提供受控号码文件后完成。本条完成前不声称真实短信提交已验收。
- 尚未用真实注册流程消费本次邀请码；单次核销与无效/已用/过期码已有 51 项后端测试和数据库条件更新覆盖，但真实新账号端到端仍待受控账号验收。
- 未接真实支付下单、回调验签、对账和退款；当前“我已付款”只能作为受开关保护的演示入口。
- 阿里云 `ACCEPTED` 只能证明供应商接受提交；运营商最终送达仍需手机侧确认或后续回执能力。

下一阶段顺序应为：受控手机号真实提交验收 → 受控账号核销验收 → 支付方案和价格确认 → 支付下单/回调验签与幂等 → 对账、退款和短信失败补偿。
