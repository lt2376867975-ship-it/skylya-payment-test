# 2026-08-27 官网 8.27 支付 UI 正式发布

## 目标与范围

- 将用户提供的桌面来源包 `Skylya 官网8.27` 纳入当前工作包，作为正式官网的新 UI。
- 最快复用已经上线的付费一次性邀请码接口，不重复开发后端、SQL 或短信链路。
- 保留旧 `Skylya 官网7.30`，不覆盖或删除，方便回看与回退。
- 正式发布只替换官网静态文件，不重启容器，不改运行配置和数据。

## 查清的真实链路

- 新来源包原本只有前端假流程：点击付款按钮只执行本地 `setTransferDone(true)`，硬编码了一个看似真实的对公账户，没有调用服务端。
- 已上线的真实接口是 `POST /api/v1/auth/invite-codes/simulate-payment`，请求体为 `{ phone }`；成功数据包含 `inviteCode`、脱敏手机号和短信提交状态。
- 该接口复用既有 User 一次性邀请码签发与 Auth 阿里云短信提交链；邀请码必须存在、未过期、未使用，并在新注册事务中原子核销一次。
- 正式官网由 `skylia-web` 挂载 `/opt/skylia/skylyatype` 对外提供，静态文件原位同步后不需要重启容器。

## 实现

- 新增工作包目录 `Skylya 官网8.27`，来源包的 `src`、`public`、包管理文件与配置完整纳入；未带入来源 `node_modules`、旧 `dist`、`.git`、`.env` 或日志。
- 修改 `Skylya 官网8.27/src/components/MembershipModal.jsx`：
  - API 基址使用 `VITE_API_BASE_URL`，默认 `/api/v1`；
  - 用户确认手机号后，点击“模拟我已付款”调用现有后端接口；
  - 增加处理态、结构化失败提示和成功结果；
  - 成功时显示邀请码、脱敏手机号、短信提交状态和“只能使用一次”说明；
  - 将硬编码收款账户替换为“演示模式（非真实收款账户）/请勿进行真实转账”；
  - 页面明确说明当前不产生真实扣款，按钮改为“模拟我已付款”。
